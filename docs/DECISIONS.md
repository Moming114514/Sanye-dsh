# 架构决策记录（DECISIONS）

> 记录「为什么这么选」以及「什么信号说明该重新考虑」。每条包含：背景 / 选择 / 代价 / 复查点。
> 维护规则：每新增 10 个补丁标记，必须在这里写一条评估。

## D-001 人格分四层（核心 / 语气 / 场景 / 日常）

- 背景：0.8.1 上游把人格卡按场合分层注入，群聊只装语气层，省 token。
- 选择：沿用上游分层；额外补 `persona.daily.md` 与 `persona.scenes/*`（群里加 300 字核心，解决“没底气”）。
- 代价：两处文件要同步维护；群聊省下的 token 被 300 字核心抵消一部分。
- 复查点：若群里仍频繁“顺着别人评价走”，考虑群聊改注入全量核心（需把 `role.maxInjectChars` 提到 7500）。

## D-002 补丁 → 扩展钩子（M2）

- 背景：`bridge.js` 一周内累积 96 处 `_PATCH`，加功能要在多处登记。
- 选择：抽出 6 个钩子（route/promptBlocks/stateKey/onGroupMessage/onPrivateMessage/wakeGate/afterSend）+ `src/ext/` 模块化，`_PATCH` 降到 74。
- 代价：迁移期改动面大、需要逐模块验证；旧补丁与新钩子并存一段时间。
- 复查点：再加 10 个补丁仍超过 3 处登记 → 继续把 `bridge.js` 剩余块迁出。

## D-003 一级注意力判定（本地打分，零成本）

- 背景：群消息一条条唤醒，大量是不值得接的话，花钱且显得话痨。
- 选择：本地打分（叫名字 +4、问句 +2、求助 +2、长度≥8 +1；@别人 −3、太短 −2、只有图 −2、重复 −3），低于阈值不唤醒；不调用模型。
- 代价：阈值偏严会漏掉该接的话；需要日志观察误杀。
- 复查点：连续一周出现“该接没接”，把 `minScore` 从 2 降到 1。

## D-004 记忆注入用「短句 + 框架」，不用原话

- 背景：学说法样本是长句，直接注入会占预算、且她照搬像演戏。
- 选择：样本加 `short`（可直接说的一句）与 `why`（框架），注入优先用 `short`。
- 代价：长样本要人工/脚本拆短句；拆得不好会失去原味。
- 复查点：若注入后她的句式没有变化，说明短句抽取太保守，改人工挑选。

## D-005 免费额度只用于「可重跑、不敏感」的支线

- 背景：学生预算有限，WorkBuddy 白嫖 / MiniMax 赠金都不可持续。
- 选择：主链路只用官方 deepseek-flash；免费额度只给开发杂活与字幕摘要等可重跑任务；不自动回落（回落逻辑出错会让她静默不回）。
- 代价：省不了主链路的钱，只能省辅助任务。
- 复查点：若官方涨价或额度受限，再评估模型路由（backlog 已记录）。


## D-006 插件接入顺序：契约先行

- 背景：外部高星插件（记忆/检索/面板）想接进来，但数据模型与生命周期不同，直接耦合会互相拖死。
- 选择：先写 `docs/PLUGIN-CONTRACT.md`（7 个钩子 + 6 条契约 + 5 步接入流程），V1 只做契约与只读示例（`github-learn`），真正接第三方留 V2。
- 代价：接入要写 adapter，多一层；但换插件时只换 adapter。
- 复查点：连续两个插件都需要改 `bridge.js` → 说明契约不够，补契约而不是补特例。

## D-007 本地检索（向量）：等等再上

- 背景：现在召回是倒排索引（590 条 0.34ms），缺「换个说法也能查到」。
- 选择：暂不做 bge-small + ONNX（约 100MB 模型 + 150MB 内存），先攒失败案例（她「想不起来」时记一条），满 20 条再评估。
- 代价：这期间召回仍受关键词限制。
- 复查点：失败案例里「同义不同词」占比 >50% → 上向量。

## D-008 提示词语言分工

- 背景：中文规则冗长；但语气细节翻成英文会丢。
- 选择：**骨架用英文**（`LANGSPEC_PATCH`，注入 `[Speaking spec]` 一段，约 500 字符），语气/例子/边界仍用中文层，末尾强制中文输出；`role.langStyle='zh'` 可一键回退。
- 代价：两套语言并存的提示词略难读；需要观察英文规约是否真的被遵循。
- 复查点：若一周内仍频繁出现「三条并列/评论自己上一句」，说明英文规约没生效，考虑改回中文并把规则写进语气层示例。

## D-013 提示词：易变段必须在末尾
- 背景：`buildWakePromptV2` 的 base 拼接里，`closureLine`、`replyLine`（含秒级静默倒计时）、`biliLine`（含最近消息 recall）每轮都会变；它们夹在稳定段中间，导致提示词缓存前缀每轮被打断（命中 ¥0.02/百万 vs 未命中 ¥1/百万）。
- 决定：这三段整体移到 base 末尾（`mediaRuleLine` 之后），相对顺序 closureLine → replyLine → biliLine；拼接表达式处留注释 `/* CACHEORDER2: 易变段必须在末尾，新增易变段请追加到此处 */`。
- 约束：只动顺序，不改任何段落内容；以后新增「每轮会变」的段，一律追加到这条注释之后。
- 验证：抽取 base 表达式比对，25 段多重集相同、顺序变化符合预期（P2-K，2026-11-06）。
