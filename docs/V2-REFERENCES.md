# V2 参考清单（只看不动）

> 规则：**V1 不融合任何外部插件**。这里只记录「看到什么、好在哪、值不值得抄、许可如何」。
> 每条写清：来源 / 亮点 / 可复用点 / 代价 / 许可 / 结论（抄 / 参考 / 不碰）。
> 用户 2026-11-02 要求：先记录，不写代码。

## 已记录

### AstrBot
- 来源：https://github.com/Soulter/AstrBot
- 亮点：插件目录化（一个目录一个插件，自带 `plugin.json`）、多平台适配层抽象、Web 面板内置插件市场。
- 可复用点：**插件清单 + 权限声明**的格式；平台适配接口的形状。
- 代价：它是完整框架，硬合会变成两套骨架；只能「照形状重写」。
- 许可：AGPL-3.0（**有传染性**）→ 绝不拷代码，只参考设计。
- 结论：参考（不抄代码）。

### AuraBot
- 来源：链接待补。
- 亮点：人格/语气分层组织（社区传闻，未核实源码）。
- 可复用点：人格文件的目录布局与「场景卡」写法。
- 结论：参考，等拿到链接再核实。

### four-point-hooks（社区 PR #1）
- 来源：`src/ext/four-point-hooks.js`（PR 未合）。
- 亮点：七个入口收成四处；每扩展独立 try/catch；`stateKey` 只算 cache 扩展。
- 可复用点：**每扩展隔离**（我们踩过 afterSend 中断的坑）。
- 结论：借鉴思路；等 V2「入口收拢」时重写。

### dsh-pond
- 来源：https://github.com/Oii6111/dsh-pond
- 亮点：B 站「搜→读字幕→判断→写报告」的流水线。
- 可复用点：字幕抓取与摘要的流水线形状。
- 风险：二次分发字幕、主观投毒。
- 结论：暂缓。

## 评估维度（以后加条目照这个写）

1. 它解决的**具体问题**我们有没有；
2. 能不能**只抄一块**（函数/格式），而不是整套框架；
3. **许可**是否传染（GPL/AGPL 只参考，不拷）；
4. 维护成本（多一套依赖 = 多一个坏点）；
5. 是否影响 V1 稳定性（影响 → 必进 V2）。
