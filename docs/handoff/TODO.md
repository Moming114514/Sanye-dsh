## 待评估（用户提的，等合适时机再做，别插进 W1/W2）

### B-1 命令前缀可配置（避免触发别的机器人）

**诉求**：不想在群里发 `/帮助` 时把别的机器人也调出来（它们也监听 `/`）。想换成别的符号，但仍保留私聊用 `/`。

**现状实测**（2026-11-03 20:2x）：

- `src/bridge.js` 里 `startsWith('/')` 共 **8 处**：3205、13465、14504、15708、16049、16054、16208、16683；
- 命令分发主体在 **16054~16240**：`cmdLine.startsWith('/')` 之后用「首词」匹配（16070/16140/16233 是 `/帮助`、`/静音`、`/状态` 的数组），所以**换前缀 = 把这些数组里的字面量也改成新前缀**，不只是改 startsWith；
- 另有 14504 处：群里「管理员发斜杠命令」被排除接话；16683 处：群里非斜杠内容走别的分支。

**建议方案**（做的时候三选一，先问用户）：

1. **可配前缀**：`socialV2.commandPrefix`（默认 `/`），解析时统一 `cmd.startsWith(prefix)`，数组匹配先剥前缀再比；
2. **双前缀兼容**：群内认 `。`（中文句号，几乎不冲突）+ 私聊保持 `/`；
3. **仅换群内**：私聊永远是 `/`，群内用新前缀（推荐，误触最少）。

**代价**：约 1~2 小时、1 次重启；要改 8 处判定 + 3 组命令名字面量 + 帮助文案 + 命令大全页（面板 `/api/commands` 里的示例也要换前缀）。

**验收**：群里发新前缀能执行；发 `/` 不执行（且不触发别的 bot）；私聊 `/` 仍可用；`/帮助` 输出里的前缀正确。

**归属**：W3（命令层整理）或独立小任务，**不要放进 W1（清单）和 W2（迁移）**。
