# 项目说明（供外部评估）

> 面向：想给建议的朋友/同行。**请先看第 0 节约束**，再给方案——不然后面的建议大概率跑不动。

## 0. 硬约束（先看这个）

| 项 | 现状 | 含义 |
|---|---|---|
| 机器 | **2 核 / 4G（可用 3.6G）/ 40G 盘**，无 GPU | 跑不了本地大模型、向量库也吃力 |
| 预算 | **¥8/天上限**（当前实际 ¥2~4/天） | 任何“每轮多调一次模型”的方案都要先算钱 |
| 内存 | 已 OOM 杀过进程一次；靠 zram(1G)+swap(2G) 撑着 | 不能加常驻服务 |
| 定位 | **单角色个人使用**，不是平台、不做多租户 | 不需要 K8s/Docker Swarm/多实例 |
| 运维能力 | 一个人（学生），每天能花 20~30 分钟 | 方案必须能“出事自己起来” |
| 环境 | Ubuntu / Node 22 / systemd / Docker（仅 NapCat） | 没有 CI、没有监控系统 |

**明确不需要的建议**：本地大模型、GPU 推理、向量数据库、K8s、多容器编排、全量重写、前端换框架。
**欢迎的建议**：在不加内存、不加每轮调用的前提下，让“该说话时像人、不该说话时闭嘴、成本可控”。

## 1. 这是什么

一个跑在 QQ 上的个人助手角色（她是“三叶”）。核心不是“能聊天”，而是：

> **在 373 条/小时的群里，判断哪几条值得回；回了要像人；一天花费 ≤¥8。**

## 2. 架构（现状）

```
QQ ←→ NapCat（OneBot v11，docker）←→ bridge（Node，systemd）
                                          ├→ DSH（agent 运行时，调模型）
                                          ├→ MCP 工具（QQ 工具 50 个，现裁到 24）
                                          └→ 状态文件（人格/记忆/规则，全在磁盘）
面板 her-console（:7800，独立进程） ← 只读状态 + 改配置
ASR：sherpa-onnx，socket 按需启动（平时不在内存里）
```

关键设计：**人格与记忆是磁盘文件**（Markdown/JSON），进程只是壳；换运行时只改 7 个钩子（见 `docs/DECOUPLE.md`）。

## 3. 已完成（按层）

### 3.1 感知（输入）
- **看图打通**（本周最大成果）：
  - 媒体消息不再被判成“空消息”；
  - 下载统一先走 `get_image` 换新地址（不再 404）；
  - 唤醒时**自动附图**（不再依赖模型自觉去调工具）；
  - 超 8MB 自动降采样。
  - 实测：`withMedia 28 / looked 5` → 用户发图后她真的描述画面。

### 3.2 判断（要不要说话）
7 个闸门串在一条链上，按 manifest 顺序执行：

```
owner-only(10) → mute(20) → learn-mode(30) → economy(40) → group-rate(50) → attention(60) → safe-talk(100)
链外：鱼群保护、tokenGurad
```

- 每群可设：静音 / 学习模式（只看不聊）/ 只回指定人 / 省钱 / 频率（N 分钟一次、每天 N 次）；
- **注意力打分**（本地规则，0 成本）：叫名字 +4、问句 +2、求助词 +2、@ 别人 −3、太短 −2、重复 −3；
- 分数不够但热闹群可**抽样放行**（1%），但只让她回一句短话；
- 新增**发言策略适配层**（`speak-policy.js`，纯函数、只读），把 7 个闸门的判断收成一个决策点 + 日志 `[策略·预测]/[策略·实际]`，为将来合并做准备。

### 3.3 表达（怎么说）
- 人格分 4 层：核心（私聊）/ 语气 / 日常 / 场景（群聊、私聊、B站、桌宠），群聊只注入语气+场景；
- 8 条“铁律”（一次一个理由、句尾语气词只留一个、不评论自己上一句、被纠正 15 字内改口…）；
- 禁 3 种句式（评价+自我类比、评价+自我陈述、评论自己上一句）+ 13 个 AI 套话词；
- 学说法：只学一个人（群里那只机器人），学“框架”不学口头禅，样本带「短句 + 框架」两个字段。

### 3.4 记忆
- 记忆卡 600 条、注入 24 条/≈2600 字；分档 clarity（vivid/clear/fuzzy），60 天没提及才遗忘；
- 关联召回：每条消息按关键词从 600 条里挑 3 条注入（倒排索引，0.34ms）；
- 记忆按会话隔离（群看不到私聊记忆）。

### 3.5 成本（实测）
- 近 24h：¥2~4 / 上限 ¥8；每轮均价 **¥0.02**；
- 钱花在哪：**缓存未命中输入占 ~50%**、命中 24%、输出 5%、峰时加成 13%；
- 已做：人格 1.36 万 → 0.91 万字符、工具 schema 50 → 24 个（−44%）、节省**每次冷启动约 ¥0.1**。

### 3.6 运维
- systemd 托管 + watchdog（2 分钟探活）+ 自检（30 分钟）+ 每日快照 + 每月归档；
- 面板「总览」一屏看：服务/端口/磁盘/今日花费/心情/记忆/媒体；
- 出问题自动重启；异常每天 18:00 汇总一次 QQ 提醒。

## 5. 想请对方评估的具体问题

1. **多话题选择**：群里 3 个人同时说话，怎么低成本挑“最值得接的那条”？（我们现在只有“回最新/回@我/回叫我名字”）
2. **记忆注入**：600 条里每轮挑 3~5 条，除了关键词倒排，有没有**零内存成本**的更好办法？
3. **判停**：她有时“该沉默却接话”，有时“该接却沉默”。有没有**低成本的可观测指标**能定位是哪一层判错（不是靠人肉看聊天记录）？
4. **成本**：在不加模型调用次数的前提下，还有哪些地方能再省？（已知：人格精简、工具裁剪、减少重启）
5. **稳定性**：2C4G 上，systemd + watchdog + 自检这套够不够？有没有“不加重”的兜底手段？

## 6. 我们的取舍（以免被建议成另一套系统）

- **不做多角色/多租户**：一个人用，单实例；
- **不做本地模型**：没 GPU，API 更便宜；
- **不做全量重构**：现在 1.8 万行的 bridge 里 74 个补丁标记，正在用“扩展钩子 + manifest”逐步收拢；
- **不追求“最强模型”**：追求“最便宜的模型 + 足够好的提示词 + 能判停”。
