# R0 · bridge.js 瘦身盘点（只读结论）

> 2026-11-06 12:2x 实测，`wc -l src/bridge.js` = **18,632 行**（任务书写的 18,091 是旧值，期间新增了 P2/Q 系列）。
> 目标：≤12,000 行，行为零变化。本文只给结论与清单，未改任何代码。

## 0. 结论先行

1. **90% 的代码在一个函数里**：`main()` 从 `1861` 到 `18628`，共 **16,768 行**。所以「迁出」不是复制粘贴，而是把嵌套函数抽成模块、显式注入依赖（`cfg / state / bot / log / fetch`）。这是整件事的主要成本，也是所有风险的来源。
2. **最大单块是控制台**：`4460–9636`，**5,177 行（27.8%）**，231 处 `/api/` 路径。它字符数多但逻辑最机械，是压行数的主力；必须最后做，因为每条路由都闭包着 main 里的 `cfg` 与 `state`。
3. **模块级已独立的只有 1,860 行**（10%），其中真正「无 bot、无 state、无 cfg」的纯函数约 **200 行**——这就是第一步。
4. 行数只是结果指标。真正的验收是：`npm run verify`（结构快照锁工具/路由）+ `replay-hooks --diff`（12 条钩子样本）+ 提示词字节数不变 + 线上日志无新错误。

## 3. 不可迁清单（迁出即破坏行为）

| 对象 | 行号 | 原因 |
|---|---|---|
| `bot` 实例与事件注册 | 18233–18628 | `SnowLumaWebSocketClient` 在 main 内构造，`on('open'/'close'/'error')` 直接引用 main 的 `cfg/state/sessionEpoch`；移出需要把整个连接生命周期重写 |

## 5. 第一步为什么是它

- 它已经在模块作用域（不在 `main()` 里），**没有闭包可丢**，迁移只是移动文件 + 加 import。
- 输入输出都是普通值（segments 数组 ↔ 字符串），不碰 bot、不碰 state、不读写文件。
- 现成对照物最多：提示词里的 `[图片]/[表情包]/[动图]/[语音转写]` 都由它生成，`replay-hooks` 的 12 条样本 + `/api/socialV2/prompt` 字节数 + 现有单测可以三方同时证明「行为没变」。
- 回滚成本最低：一个 commit、两个新文件，revert 即恢复，不需要重启 bridge 验证（下一次重启自然生效）。
- 唯一要小心的是：`segmentsToText` 在 4 处被调用（消息入库、唤醒提示词、面板预览、回放脚本），迁移后要把这些调用点一起改；任何一处漏改，`verify` 的语法和单测都不会红，只有线上才看得出来——所以第 1 步的验收里必须加一次「私聊发图 → 提示词含 `[图片]`」的实测。
