# 记忆按话题挑选（MEMORY-TOPIC）— 设计稿

> 目标：把「每轮固定注入 24 条记忆」改成「按当前话题挑 6~8 条 + 保留固定骨架」，
> 让记忆真正被用到（当前实词重合度 0.07 = 记忆没送到眼前）。
> 只改注入侧，不改记忆存储格式。

## 为什么

- 现有 `renderMemoryCard()` 按节 + 优先级固定挑 24 条（约 2600 字），与"这句话在说什么"无关；
- 实测她回复与用户消息的实词重合度仅 **0.07** → 说明"该想起的那条"没被送到眼前；
- 人设简化之前必须先解决这个，否则会变成"既没性格也想不起事"。

## 设计

### 1. 输入
- 当前消息文本 `text`（群聊时加上最近 2 条上文的 `plain`）；
- 记忆全量 `memory/memory-card.json`（已有倒排索引 `src/ext/related-memory.js`，590 条 0.34ms）。

### 2. 打分（本地，零 API 成本）
```
score = Σ log(1 + N/df(gram))            // 与现有 relatedMemoryBlock 同公式
      + 0.3 * (importance / 100)          // 重要度加成
      + 0.2 * (pinned ? 1 : 0)            // 钉住
      + 0.15 * recency(14 天线性衰减)     // 近期
      - 0.4 * (clarity === 'fuzzy' ? 1 : 0) // 模糊条目降权
```

### 3. 选择
- 取 top 8，但**每个 source（qq/bili/owner/群号）最多 2 条**，避免全是同一来源；
- 至少保留固定骨架 4 条：初次相遇 1 + 永远不会忘 1 + 最近 7 天 2（这些不参与打分）；
- 总预算 **800 字**（约为现在 2600 字的三分之一），超出按分数截断。

### 4. 注入格式
```
【你现在想起的事（和这句话有关的）】
- 10-31 [清晰] 他半夜两点还在改配置，说「再试一次」
- 11-02 [清晰] 他说过不喜欢我催他吃饭
（想不起更多就用 qq_recall_memory 查，不要编）
```

### 5. 开关与回退
```json
"socialV2": {
  "memoryTopic": {
    "enabled": true,
    "maxItems": 8,
    "maxChars": 800,
    "perSource": 2,
    "skeleton": 4
  }
}
```
- `enabled:false` → 回到原 `renderMemoryCard()` 的 24 条固定注入（零风险回退）；
- 两者不同时启用，避免重复注入。

### 6. 验收
1. `/api/socialV2/prompt` 里出现「【你现在想起的事」段，字数 ≤ 800；
2. 用 5 个真实问题（"那个视频"、"生日"、"熬夜"、"头像"、"考研"）手工比对新旧注入，相关条数应提升；
3. 观察 24 小时：`/api/human-stats` 的实词重合度（目标 0.07 → ≥0.12）、句长中位数不下降；
4. 若效果变差：`enabled:false` 一键回退。

## 不做

- 不做向量检索（等失败案例攒够 20 条再评估，见 DECISIONS D-007）；
- 不改记忆存储结构、不加新模型调用。
