## 1. 这能用吗？装完就能跑？

**不能，它不是产品。** 这是一份**参考实现**：底座是上游 [SurfCore](https://github.com/Mieksido/surfcore) v0.8.1（MIT），我在上面做了一周多的改造，把「怎么让 QQ 机器人长期可用」这件事的具体做法写成了可读的代码。

要跑起来你得自己准备：

- Linux（Debian 12 实测；systemd、`runuser`、`ps` 都是 Linux 写法）
- Node 22
- 一个 OneBot v11 实现（NapCat 实测；SnowLuma 理论上可用，见 [`CHANNEL-COMPAT.md`](CHANNEL-COMPAT.md)）
- DSH 本体，和一个能用的模型 key
- 手写 `config.json`、写一份你自己的角色卡

`docs/INSTALL.md` 写的是「思路与坑」，**没有一键脚本**——那件事排在 V2（见 [`V2-ROADMAP.md`](V2-ROADMAP.md)），得有人真需要才做。

## 2. 我用的 SnowLuma，不看 NapCat，能用吗？

**能用，而且桥接本来就是 SnowLuma 那一套**：依赖里是 `@snowluma/sdk`，配置键是 `snowluma.wsUrl / httpUrl`。我只是把这两个地址指向了 NapCat 的 3000/3001。

差异只在「通道实现了哪些 OneBot 扩展 API」：

| 能力 | 影响 |
|---|---|
| `get_cookies` | QQ 空间自动看说说 / 评论。不支持就**自动停用**，只记一条日志 |
| 表情云收藏（`add_custom_face` 等） | 收藏到 QQ 表情夹。不支持就只写本地库 |
| `*_msg_history` | 读群/好友历史（学说话、看图）。大多数实现都有 |

启动 3 秒后会探一次并把结果写进 `state/channel-caps.json`，面板排障页能看。细节见 [`CHANNEL-COMPAT.md`](CHANNEL-COMPAT.md)。

## 4. 代码质量怎么样？是不是一堆补丁？

**上游是别人的，我做的主要是「拆补丁」。**

起点是 106 处内联补丁（`// XXX_PATCH` 直接插在 `bridge.js` 里），现在收敛成：

- **6 个钩子**：提示词块 / 状态缓存键 / 唤醒闸门 / 群消息前 / 私聊前 / 发送后
- **29 个扩展模块**（`src/ext/`），每个自己管状态文件、自己的路由、自己的提示词块
- **1 套验收**：`node scripts/verify.mjs` = 语法 + 单测 + 提示词结构快照 + MCP 工具清单 + 路由状态码

不吹架构多好，但**每次改动都能复核、都能回滚**——这是「敢在线上改」的前提。设计说明在 [`src/ext/ARCHITECTURE.md`](../src/ext/ARCHITECTURE.md)。

## 5. 6 个钩子够用吗？为什么不做插件系统？

**钩子够用，插件系统是另一件事。**

钩子解决的是「改一处不影响别处」，插件解决的是「别人只想要其中一件功能」。后者需要：权限边界、版本兼容、依赖声明、错误隔离、预算控制——现在只有 `src/ext/` 的模块约定（工厂 + 依赖注入 + 懒取防 TDZ），够我自己用，不够分发。

真要插件化，见 [`V2-ROADMAP.md`](V2-ROADMAP.md) 第 3 条，触发条件是「分享之后真的有人只想要某一件」。

## 6. 为什么内存里 500 多条记忆，索引还这么快？

因为召回走**倒排索引**（`gram → 记忆下标`），不是每次遍历全表重新切词。实测 590 条记忆、5 条典型问句：

| | 单次召回 |
|---|---|
| 遍历全表 | 6.93 ms |
| 倒排索引 | **0.34 ms** |
| 输出一致性 | 逐字节相同（md5 校验过）|

没有换 SQLite，是因为现在还不需要——触发条件是「条数上 3000」或「并发写」，写进 V2 了。

## 7. 花多少钱？会不会失控？

以「1 个主人 + 3 个群」这一周的实测：

- 聊天：¥0.02~0.05 / 轮（缓存命中率 95%+ 时）
- 每天：¥2~7（上限写死 ¥7/天，花到 80% 提示词里会提醒她自己收敛）
- B 站看视频：¥0.1~0.5 / 天（贵在抽帧，不在字幕）

三道闸门：`maxDailyCostCNY`（日上限）、`downgradeAtRatio`（到 50% 自动降档）、面板「花费」页（实时 + 每天快照）。

省钱最大的杠杆不是「话少」，是**缓存命中**：把每轮都会变的内容（时间、状态、唤醒原因）放到提示词最尾部。这一条在 README 的「我解决的 5 个问题」里有写。

## 8. 换我自己的角色卡，要改多少？

**只改两个文件，不碰代码**：

- `characters/<你的角色>/persona.md` —— 核心层（身份、称呼、边界）
- `characters/<你的角色>/persona.tone.md` —— 语气层（性格、说话方式、群规、何时沉默）

群聊只注入「身份底座 + 语气 + 场景 + 日常」，私聊才注入全量。所以——**群里也必须守的规矩，要写在语气层**，写在核心层等于群聊里不存在。

写法要点见 [`LEARN-FROM-ME.md`](LEARN-FROM-ME.md) 第 1 节。

## 11. 为什么不把这些做成一个能直接分发的应用？

因为**风险不在打包，在责任**：一个能直接跑起来的 QQ 机器人，意味着作者的账号、别人的隐私、平台规则都在里面。我不想让「一键安装」变成「一键踩坑」。

参考实现 + 明确的边界 + 可复现的验收，是我能负责的形态。

## 12. 这套东西现在稳定吗？

**一周多的实盘**，不是玩具也不是生产级：

- 桥接 = systemd 托管（`Restart=always`）+ 看门狗（3001 连接 + 3100 端口）
- 崩溃、断线、重启都有自愈；QQ 被踢下线是**唯一**必须人工处理的场景
- 每天花费有上限，改配置有「待生效」提示，改坏了能一键重启回滚

但请当作「参考实现」：**能跑、能看懂、能改，不代表适合别人拿去托管重要账号**。
